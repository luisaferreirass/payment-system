# 💳 Payment System

## 📝 About the project

A **PIX** payment system built with **Flask**, implementing QR Code generation, real-time communication via **WebSockets** and automatic payment confirmation. The project simulates a complete digital payment flow with a responsive web interface.

Great for learning:
- PIX payment systems
- QR Code generation
- WebSockets with Flask-SocketIO
- Real-time communication
- Webhooks for payment confirmation
- Flask-SQLAlchemy and SQLite
- Template rendering with Jinja2
- MVC architecture

## 🚀 Technologies used

- **Python 3.x**
- **Flask 2.3.0** - Web framework
- **Flask-SQLAlchemy 3.1.1** - Database ORM
- **Flask-SocketIO 5.3.6** - WebSockets for real-time communication
- **SQLite** - Database
- **QRCode 7.4.2** - QR Code generation
- **Pillow 10.2.0** - Image processing
- **Pytest** - Testing framework
- **Jinja2** - Template engine

## ⚙️ How to run

### Prerequisites

- Python 3.x installed
- pip (Python package manager)

### Installation

1. Clone the repository:
```bash
git clone https://github.com/luisaferreirass/payment-system.git
cd payment-system
```

2. Create a virtual environment (recommended):
```bash
python -m venv venv
```

3. Activate the virtual environment:
```bash
# Windows
venv\Scripts\activate

# Linux/Mac
source venv/bin/activate
```

4. Install the dependencies:
```bash
pip install -r requirements.txt
```

5. Initialize the database:
```bash
python
>>> from repository.database import db
>>> from app import app
>>> with app.app_context():
...     db.create_all()
>>> exit()
```

### Running the application
```bash
python app.py
```

The application will be available at: `http://localhost:5000`

### Running the tests
```bash
pytest
```

or, for more details:
```bash
pytest -v
```

## 🎯 Features

- 💳 **Create a PIX payment** with an amount and expiration date
- 🔲 **Automatically generate a QR Code** for payment
- ⏰ **Automatic expiration** after 30 minutes
- 📱 **Responsive web interface** to view the payment
- ✅ **Webhook confirmation** simulating a bank
- 🔄 **Real-time updates** with WebSockets
- 📊 **Confirmation page** after payment
- 🚫 **Custom 404 error page**

## 🛠️ Data model

### Payment

| Field | Type | Description |
|-------|------|-----------|
| id | Integer | Primary key (auto-increment) |
| value | Float | Payment amount |
| paid | Boolean | Payment status (default: False) |
| bank_payment_id | String(200) | Unique ID generated by the "bank" |
| qrcode | String(100) | QR Code file name |
| expiration_date | DateTime | Expiration date (30 minutes) |

## 📸 API Endpoints

### PIX Payments

| Method | Endpoint | Description |
|--------|----------|-----------|
| POST | `/payments/pix` | Creates a new PIX payment |
| GET | `/payments/pix/<id>` | Shows the payment page |
| GET | `/payments/pix/qr_code/<file_name>` | Returns the QR Code image |
| POST | `/payments/pix/confirmation` | Bank confirmation webhook |

### WebSocket Events

| Event | Description |
|--------|-----------|
| `connect` | Client connects to the server |
| `disconnect` | Client disconnects from the server |
| `payment-confirmed-<id>` | Payment confirmed notification |

## 💡 Usage examples

### 1. Create a PIX payment
```bash
POST /payments/pix
Content-Type: application/json

{
  "value": 100.50
}
```

**Response:**
```json
{
  "message": "The payment has been created",
  "payment": {
    "id": 1,
    "value": 100.50,
    "paid": false,
    "bank_payment_id": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
    "qrcode": "qr_code_payment_a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
    "expiration_date": "2024-02-04T11:00:00"
  }
}
```

### 2. View the payment page
```bash
GET /payments/pix/1
```

Returns an HTML page with:
- Payment amount
- Generated QR Code
- Active WebSocket connection
- Expiration timer

### 3. Get the QR Code image
```bash
GET /payments/pix/qr_code/qr_code_payment_a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8
```

Returns the QR Code as a PNG image.

### 4. Confirm the payment (bank webhook)
```bash
POST /payments/pix/confirmation
Content-Type: application/json

{
  "bank_payment_id": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "value": 100.50
}
```

**Response:**
```json
{
  "message": "The payment has been confirmed"
}
```

**Result:** 
- Marks the payment as `paid = True`
- Emits the `payment-confirmed-1` WebSocket event
- The client is automatically redirected to the confirmation page

## 🔄 Payment Flow
```
1. Client creates a payment
         ↓
2. System generates a QR Code and unique ID
         ↓
3. Client opens the payment page
         ↓
4. WebSocket connects and waits for confirmation
         ↓
5. "Bank" sends the confirmation webhook
         ↓
6. System validates and confirms the payment
         ↓
7. WebSocket notifies the client in real time
         ↓
8. Client is redirected to the success page
```

## 🔐 Implemented Validations

### Payment Creation
- ✅ Checks that an amount was provided
- ✅ Generates a unique ID using UUID
- ✅ Sets a 30-minute expiration
- ✅ Saves the QR Code to disk

### Payment Confirmation
- ✅ Validates `bank_payment_id` and `value`
- ✅ Checks that the payment exists
- ✅ Prevents duplicate confirmation
- ✅ Validates that the amount matches
- ✅ Updates the status in the database
- ✅ Notifies the client via WebSocket



## 🎯 PIX System Features

### QR Code Generation
- Unique ID using UUID4
- Automatically generated payment hash
- PNG image saved in `/static/img/`
- Pattern: `qr_code_payment_{bank_payment_id}.png`

### Bank Simulation
- Generation of a unique `bank_payment_id`
- Confirmation webhook
- Amount and ID validation
- Duplicate protection

### Payment Expiration
- Default time: 30 minutes
- Stored in `expiration_date`
- Can be used for automatic cleanup
